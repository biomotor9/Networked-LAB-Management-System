# 项目管理功能规格与实施方案

> 状态：产品规则已确认，等待实施
> 确认日期：2026-08-14
> 适用范围：Atlas ELN 第一版多项目管理功能

## 1. 目标

把当前“每个团队只有一个默认实验项目”的工作区扩展为真正的多项目工作区。项目是大型实验研究的组织容器，负责统一管理成员、状态、资料和项目内实验计划，但项目自身不是实验节点，也不出现在计划网络图中。

一个项目可以包含多个独立的顶级实验计划。项目内不同顶级计划可以建立执行依赖；所有计划、正文、事件和附件必须归属于一个明确项目。

## 2. 术语与核心不变量

### 2.1 术语

- **团队管理员**：当前团队角色 `owner` 的产品名称。可以看到并管理团队内全部项目。
- **项目负责人**：项目内唯一的负责人，负责项目成员、状态、完成和归档。
- **项目成员**：可以参与和编辑项目内科研内容的团队成员。
- **只读成员**：只能查看项目内容和下载附件的团队成员。
- **应急编辑**：团队管理员未加入项目时，以明确原因临时修改科研内容的受审计模式。
- **归档**：项目退出日常项目列表，但仍保留数据、权限和原生命周期状态。

### 2.2 不变量

1. 一个实验计划只能属于一个项目。
2. 一个计划的全部后代必须与该计划属于同一项目。
3. 计划依赖只能连接同一项目内的计划，不能跨项目。
4. 项目不是计划，不具有父计划、实验步骤、实验结果或网络图坐标。
5. 每个项目恰好有一位项目负责人。
6. 项目成员必须先是同一团队的有效成员。
7. 项目名称在团队内唯一；忽略名称首尾空格和英文大小写。
8. 已归档项目仍占用原名称；永久删除后才释放名称。
9. 团队管理员自动拥有项目管理和查看权限，但不会自动成为项目成员。
10. 未选择项目时，系统不得创建无项目归属的计划。

## 3. 项目数据

### 3.1 第一版字段

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，团队内规范化后唯一 |
| 描述 | 选填，用于说明研究目标和范围 |
| 生命周期状态 | `筹备中`、`进行中`、`暂停`、`已完成` |
| 归档时间 | 空表示未归档；有值时界面状态显示为“已归档” |
| 项目负责人 | 必填且唯一，必须是有效团队成员 |
| 项目成员 | 普通成员或只读成员 |
| 开始日期 | 选填 |
| 结束日期 | 选填 |
| 标签 | 沿用实验计划标签规则 |
| 版本号 | 用于项目详情乐观并发控制 |
| 创建与更新时间 | 由服务器记录 |

项目不包含计划进度、预算、多负责人、自定义字段或项目编号。

### 3.2 状态与颜色

项目状态颜色与实验节点状态体系保持一致：

| 界面状态 | 颜色 |
| --- | --- |
| 筹备中 | 灰色 |
| 进行中 | 蓝色 |
| 暂停 | 橙色 |
| 已完成 | 绿色 |
| 已归档 | 绿色 |

归档是独立属性，不覆盖生命周期状态。恢复归档项目后，项目回到归档前的生命周期状态。

项目负责人手动确认项目完成。项目内仍有未完成计划时允许完成，但必须列出未完成计划并二次确认。

项目负责人和团队管理员都可以归档任意生命周期状态的项目。归档非完成项目时必须二次确认。

## 4. 权限模型

### 4.1 权限矩阵

| 操作 | 团队管理员（未加入项目） | 项目负责人 | 项目成员 | 只读成员 |
| --- | --- | --- | --- | --- |
| 查看项目与科研内容 | 允许 | 允许 | 允许 | 允许 |
| 创建项目 | 允许 | 允许，创建后成为负责人 | 允许，创建后成为负责人 | 允许，创建后成为负责人 |
| 编辑项目基本信息 | 允许 | 允许 | 拒绝 | 拒绝 |
| 管理项目成员 | 允许 | 允许 | 拒绝 | 拒绝 |
| 更换项目负责人 | 允许 | 允许，转交后失去负责人权限 | 拒绝 | 拒绝 |
| 创建和编辑科研内容 | 默认拒绝 | 允许 | 允许 | 拒绝 |
| 管理项目内依赖 | 默认拒绝 | 允许 | 允许 | 拒绝 |
| 删除普通计划 | 应急编辑后允许 | 允许 | 仅限自己创建且无后代、无依赖的计划 | 拒绝 |
| 完成、归档、恢复项目 | 允许 | 允许 | 拒绝 | 拒绝 |
| 永久删除空项目 | 允许 | 允许 | 拒绝 | 拒绝 |
| 永久删除非空项目 | 允许 | 拒绝 | 拒绝 | 拒绝 |

项目创建者自动成为唯一负责人。负责人不能在没有继任负责人的情况下退出项目或移除自己；团队管理员可以强制更换负责人。

项目负责人只能从现有团队成员中添加项目成员，不能在项目界面创建团队账号，也不能授予团队管理员角色。

### 4.2 团队管理员应急编辑

团队管理员未加入项目时，项目科研内容默认只读。需要修改时可以：

1. 将自己加入项目，按项目成员权限正常编辑；或
2. 进入仅对当前项目有效的“管理员应急编辑”模式。

应急编辑必须满足：

- 进入时填写非空操作原因；
- 页面持续显示“管理员应急编辑中”；
- 离开当前项目、退出登录或主动结束后立即失效；
- 每次科研内容修改都记录管理员、原因、时间、项目和修改对象；
- 不把管理员伪装成项目负责人或项目成员。

## 5. 页面与交互

### 5.1 左侧项目导航

当前左侧“快速访问 / 所有计划”区域替换为项目导航。常态布局：

```text
项目                                      搜索图标  ＋

● 项目 A
● 项目 B
● 项目 C
```

搜索态布局：

```text
[ 搜索项目……                         × ]  ＋
```

交互规则：

- 搜索按钮与“＋”在同一行；“＋”位置固定。
- 点击放大镜后，搜索框在原位置向左展开并自动获得焦点。
- 按 `Esc`、点击“×”，或清空后失焦，恢复放大镜状态。
- 搜索名称、描述、负责人和标签。
- 常态只显示未归档项目，并按最近访问时间排序。
- 普通关键词同时搜索未归档和已归档项目；归档项目名称命中时显示。
- 搜索“已归档”时显示全部有权查看的归档项目。
- 搜索无结果时显示“未找到项目”，但保留新建按钮。
- 项目行显示状态颜色点和名称，不显示计划进度。
- 颜色点必须提供可访问状态名称；不能只靠颜色传递状态。
- 归档搜索结果显示为“已归档 · 原项目名称”，但不修改持久化名称。

### 5.2 未选择项目

- 隐藏计划搜索、领域筛选、导入导出、视图切换和新建计划入口。
- 中间区域显示“请选择一个项目以查看实验计划”。
- 有创建权限时同时显示创建项目入口。
- 不加载任何项目的计划、正文、事件或附件。
- 右侧详情栏隐藏，或显示不含项目数据的简短说明。

进入计划管理时优先恢复用户上次访问的项目。项目不存在或用户失去权限时回到未选择状态。

### 5.3 选择项目

- 左侧保持明确选中状态。
- 页面地址包含项目 ID，刷新或复制地址后可回到该项目。
- 中间区域只加载当前项目的计划、依赖、正文、事件和附件。
- 顶部计划搜索、领域筛选、列表和网络图都限制在当前项目。
- 新建计划自动归属于当前项目，不重复询问项目。
- 请求期间显示项目加载状态，禁止短暂显示上一个项目的数据。
- 快速切换项目时取消或忽略旧请求，旧响应不得覆盖新项目。
- 无访问权限时显示稳定的 403 提示，不泄露项目名称、成员或内容。

### 5.4 创建与编辑项目

点击左侧“＋”后，不打开项目管理弹窗，而是在右侧详情栏显示新建表单：

- 名称必填；描述、日期和标签选填；默认状态为“筹备中”。
- 真正提交表单时才创建数据库记录，不预先生成半成品项目。
- 创建者自动成为负责人。
- 创建成功后自动选择该项目，并显示空项目引导。
- 取消后恢复此前详情内容。

项目详情栏包含三个页签：

1. **基本信息**：名称、描述、状态、负责人、起止日期和标签；
2. **成员与权限**：负责人、普通成员和只读成员；
3. **项目资料**：项目级附件和项目活动记录。

项目详情使用明确的“保存”按钮。切换项目或关闭详情栏时，如有未保存内容，提示保存或放弃。保存时携带版本号；版本冲突返回 409，不得静默覆盖他人修改。

### 5.5 项目详情与计划详情切换

- 点击左侧项目：右侧显示项目详情。
- 点击计划列表项或网络节点：右侧切换为计划详情。
- 再次点击当前项目，或点击“返回项目详情”：恢复项目详情。
- 右侧标题明确标识当前对象是项目还是实验计划。
- 项目管理不使用独立管理弹窗；永久删除、未保存变更等确认提示不受此限制。

### 5.6 空项目

项目创建成功但没有计划时，中间区域显示：

- 项目名称及空状态说明；
- “新建第一个实验计划”入口；
- 导入当前项目备份入口。

## 6. 计划归属、依赖与移动

### 6.1 创建与依赖

- 只有选择项目后才能创建计划。
- 顶级计划和下级计划均自动归属当前项目。
- 项目内不同顶级计划之间允许建立依赖。
- 现有“同一层级才允许建立执行依赖”的规则继续生效，因此顶级计划之间可以连接，父子层级之间不能直接连接。
- 服务端必须同时验证依赖两端属于当前项目、层级一致且不会形成有向环。

### 6.2 删除计划

- 普通成员只能删除自己创建、没有后代且没有任何入边或出边的计划。
- 项目负责人可以删除任意计划，但必须先处理其后代和依赖关系。
- 团队管理员未加入项目时，必须进入应急编辑后才能删除计划。
- 删除必须记录项目级活动事件。

当前 `plans` 表尚未保存创建者，实施时必须补充 `createdBy`，才能可靠执行普通成员删除规则。

### 6.3 跨项目移动

- 一次移动完整计划子树，不能拆分父子关系。
- 操作者必须同时拥有源项目和目标项目的管理权限。
- 项目负责人只能在自己同时负责两个项目时执行；团队管理员可以执行。
- 子树与外部计划存在任何依赖时阻止移动，并列出必须先解除的依赖。
- 移动保留计划、正文、事件、附件和子树内部依赖。
- 移动是单个数据库事务；失败时源项目数据保持完整。
- 源项目与目标项目的版本号都必须增加，使其他已打开的客户端检测到冲突。

## 7. 项目附件和活动记录

### 7.1 项目附件

- 项目附件用于项目说明和公共资料，不代表具体实验结果。
- 项目负责人和普通成员可以上传。
- 上传者、项目负责人和团队管理员可以删除。
- 只读成员可以查看和下载，但不能上传或删除。
- 沿用现有单文件 20 MB 限制。
- 团队附件总量继续限制为 1 GB；额度计算必须覆盖团队全部项目，而不是仅当前项目。
- 文件名、大小、MIME 类型、路径和团队/项目权限继续使用服务端校验。

### 7.2 活动记录

项目活动至少记录：

- 创建项目；
- 修改名称、负责人、状态和日期；
- 添加、移除成员或改变成员角色；
- 创建、移动和删除实验计划；
- 完成、归档和恢复项目；
- 管理员进入、操作和退出应急编辑；
- 永久删除项目前的团队级删除事件。

项目永久删除后，团队审计记录继续保留操作者、时间、项目名称和删除内容数量，但不保留已删除科研正文。

## 8. 删除与恢复

### 8.1 权限

- 空项目：项目负责人或团队管理员可以永久删除。
- 非空项目：只有团队管理员可以永久删除。
- 项目负责人不能永久删除非空项目，只能归档。

### 8.2 永久删除确认

删除非空项目时必须：

1. 展示将删除的计划、正文、事件和附件数量；
2. 明确说明不可通过界面恢复；
3. 要求输入完整项目名称；
4. 验证操作者仍是团队管理员；
5. 先写入团队级删除审计事件，再执行删除流程。

项目数据库记录通过外键级联删除计划、正文、事件和附件元数据。附件实体文件在数据库提交后清理；清理失败必须记录可重试的失败信息，不能把数据库事务回滚成指向已删除文件的破损记录。

## 9. 导入、导出与示例数据

### 9.1 范围

- 项目负责人和项目成员可以导出当前项目。
- 只有团队管理员可以导出团队全部项目。
- 导入时必须明确目标是“新项目”还是“合并到现有项目”。
- 新项目名称冲突时要求输入新名称，不自动覆盖。
- 合并前显示冲突预览；计划 ID、层级或依赖冲突未解决时禁止写入。
- 恢复示例始终创建新的示例项目；重名时自动增加序号，不覆盖现有项目。

### 9.2 第一版备份边界

现有 JSON 备份不包含附件二进制。第一版多项目 JSON 继续保存项目元数据、成员映射、计划、依赖、正文和事件；附件实体文件仍由服务器数据库与附件卷备份流程保护。导出界面必须明确说明“JSON 不包含附件文件”，避免用户误以为已完成完整灾难恢复备份。

如产品要求从浏览器导出包含附件的完整归档，应另行设计压缩包格式、流式生成、容量上限和恢复校验，不与本次 JSON 格式升级混做。

## 10. 现有数据迁移

当前数据库已经存在 `projects` 表，且计划、依赖、正文、事件和附件均保存 `projectId`。现有约束 `projects_team_unique` 强制每个团队只能有一个项目。

新迁移必须：

1. 保留现有项目 ID，避免重写计划、正文、事件和附件关系；
2. 把现有项目重命名为“历史实验项目”；
3. 描述注明“由系统升级自动创建”；
4. 生命周期状态设为“进行中”，保持未归档；
5. 由团队内最早创建且仍有效的团队管理员担任负责人；
6. 如果不存在有效团队管理员，迁移不得生成无负责人的项目，应中止并给出可修复错误；
7. 为现有项目创建负责人成员关系；
8. 移除 `projects_team_unique`，改为团队内规范化名称唯一约束；
9. 保留所有现有计划层级、依赖、正文、事件和附件；
10. 写入一次系统迁移活动，不伪造普通成员操作。

迁移不得修改已发布的 `0000` 至 `0003` 文件，必须生成新的 Drizzle 迁移及对应元数据。

## 11. 建议数据模型

### 11.1 `projects` 扩展

建议新增：

- `description`
- `status`
- `archivedAt`、`archivedBy`
- `startDate`、`endDate`
- `tags`
- `completedAt`、`completedBy`
- 继续使用现有 `version`

名称唯一性使用团队 ID 与规范化名称的数据库唯一索引保障，不能只依赖前端检查。

### 11.2 `project_members`

新增项目成员表：

- 联合唯一键：`projectId + userId`
- 角色：`lead`、`member`、`viewer`
- `addedBy`、`joinedAt`、`updatedAt`
- 数据库层通过条件唯一索引保证每个项目只有一个 `lead`
- 写入时同时校验该用户属于项目所在团队

### 11.3 其他结构调整

- `plans` 新增 `createdBy`，用于计划删除权限和活动记录。
- `attachments.planKey` 与 `attachments.planId` 调整为可空；两者同时为空表示项目级附件，同时非空表示计划附件，并增加一致性检查约束。
- `audit_events` 建议增加可空的 `projectId` 与项目查询索引；项目删除事件在元数据中保留项目名称快照。
- 用户最后访问项目属于个人界面偏好，可以保存在浏览器；服务端不把它作为业务事实源。

## 12. API 与服务端边界

建议把当前隐式的 `/api/workspace` 单项目入口改为显式项目资源：

| 能力 | 建议接口 |
| --- | --- |
| 列出与创建项目 | `GET/POST /api/projects` |
| 读取、编辑、删除项目 | `GET/PATCH/DELETE /api/projects/{projectId}` |
| 成员管理 | `/api/projects/{projectId}/members` |
| 完成、归档和恢复 | `/api/projects/{projectId}/complete|archive|restore` |
| 读取项目工作区 | `GET /api/projects/{projectId}/workspace` |
| 保存计划与依赖快照 | `PUT /api/projects/{projectId}/workspace/replace` |
| 跨项目移动子树 | `POST /api/projects/{projectId}/plans/{planId}/move` |
| 项目级附件 | `/api/projects/{projectId}/attachments` |
| 项目活动 | `GET /api/projects/{projectId}/activity` |
| 应急编辑会话 | `/api/projects/{projectId}/emergency-edit` |

所有项目 API 都必须从会话取得团队和用户身份，并按 `teamId + projectId` 查询资源。不能仅凭客户端提交的项目 ID、角色或成员 ID 授权。

项目科研写接口统一调用项目授权函数，明确区分 `view`、`edit-content`、`manage`、`delete-nonempty` 和 `emergency-edit`，避免每条路由重复并产生不一致判断。

## 13. 客户端改造建议

当前 `workspace-client.tsx` 同时承担服务器加载、计划保存、侧栏、工具栏、网络图、详情抽屉、Markdown、事件和附件。多项目状态不应继续直接堆入该文件。

建议拆分为：

- `features/projects/model.ts`：项目类型、状态、角色和校验；
- `features/projects/project-sidebar.tsx`：项目搜索、选择和新建入口；
- `features/projects/project-drawer.tsx`：基本信息、成员、附件和活动；
- `features/projects/project-client.ts`：项目 API 调用与错误映射；
- `features/projects/access.ts`：可在服务端测试的权限决策；
- `features/workspace/plan-workspace.tsx`：当前项目内的计划工作区；
- `workspace-client.tsx`：只负责当前项目选择和各区域组合。

切换项目时必须清空或隔离：计划保存队列、版本引用、文档保存定时器、选中计划、网络焦点、附件、事件和本地视图状态。每个异步请求携带当前项目身份或使用取消信号，防止跨项目串写。

## 14. 验收清单

### 14.1 项目导航与创建

- [ ] 放大镜与“＋”同一行，搜索框原位展开，键盘可操作。
- [ ] 项目列表颜色、状态提示和选中状态正确。
- [ ] 归档项目默认隐藏，按名称或“已归档”可以搜索到。
- [ ] 未选择项目时没有任何新建计划入口。
- [ ] 新建项目只要求名称，默认筹备中，创建者成为负责人。
- [ ] 团队内项目名称忽略首尾空格和英文大小写后不能重复。
- [ ] 已归档重名项目仍阻止创建；永久删除后名称可复用。

### 14.2 项目详情与并发

- [ ] 点击项目在右侧打开项目详情，不显示项目网络节点。
- [ ] 点击计划后切换为计划详情，并能返回项目详情。
- [ ] 未保存项目修改在切换时要求保存或放弃。
- [ ] 两人并发编辑同一项目时，后提交者收到 409 冲突且不会覆盖数据。
- [ ] 加载失败、无权限、空项目和保存失败都有明确反馈和恢复入口。

### 14.3 权限与隔离

- [ ] 团队管理员能看到团队内全部项目，包括搜索到归档项目。
- [ ] 非管理员只能看到自己负责、参与或只读加入的项目。
- [ ] 项目成员不能修改成员、项目状态或归档项目。
- [ ] 只读成员不能执行任何科研写操作。
- [ ] 团队管理员未加入项目时不能直接修改科研内容。
- [ ] 应急编辑必须填写原因，限制在当前项目并记录每次修改。
- [ ] 使用其他团队或无权项目 ID 请求接口时稳定返回拒绝，不泄露数据。

### 14.4 计划、依赖与移动

- [ ] 新计划始终归属当前项目。
- [ ] 项目内顶级计划可以建立依赖，依赖环仍被拒绝。
- [ ] 跨项目依赖在客户端和服务端都被拒绝。
- [ ] 普通成员不能删除他人创建或存在后代/依赖的计划。
- [ ] 跨项目移动保留完整子树、正文、事件、附件和内部依赖。
- [ ] 存在外部依赖时移动被拒绝并列明原因。
- [ ] 移动失败不会留下部分迁移数据。

### 14.5 生命周期与删除

- [ ] 项目完成由负责人手动确认，未完成计划会触发二次确认。
- [ ] 任意生命周期状态可以归档，恢复后回到原状态。
- [ ] 负责人只能永久删除空项目。
- [ ] 团队管理员删除非空项目时必须输入项目名称。
- [ ] 非空项目删除后数据库内容、附件元数据和附件文件均被清理。
- [ ] 项目删除后团队级审计记录仍存在且不包含科研正文。

### 14.6 导入导出与迁移

- [ ] 当前项目和团队全部项目的导出权限正确。
- [ ] JSON 导出明确提示不包含附件文件。
- [ ] 名称或 ID 冲突未经用户处理时不能导入。
- [ ] 恢复示例创建新项目且不覆盖已有数据。
- [ ] 空数据库可执行全部迁移。
- [ ] 含现有单项目数据的上一生产基线可升级为“历史实验项目”。
- [ ] 升级后所有计划、依赖、正文、事件和附件仍可读取。

## 16. 第一版明确不做

- 项目模板和项目复制；
- 项目进度、看板和时间轴；
- 多负责人；
- 项目自定义字段和预算；
- 跨项目依赖；
- 外部访客、公开链接或匿名分享；
- 在浏览器 JSON 中嵌入附件二进制；
- 自动合并多人并发修改。
