# ADR-0003：版本化计划快照同步

- 状态：已接受
- 日期：2026-08-13

## 决策

计划和依赖以团队 PostgreSQL 项目为唯一事实源。客户端按 650ms 防抖提交完整计划/依赖快照；服务器在事务锁内进行结构校验、增量 upsert、删除缺失行并递增项目版本。客户端必须携带上次读取的版本，版本不一致时拒绝写入。

localStorage 仅保留文档草稿、Entry、界面状态和可导出的缓存，不再作为计划或依赖的启动读取来源。

## 原因

当前测试数据量小，而现有界面包含拖拽、图坐标、内联表单和多种依赖编辑入口。版本化快照能一次覆盖全部写入路径，同时仍把计划和依赖保存为关系表，并通过增量 upsert 保留行级创建时间和版本。它比临时维护浏览器/服务器双写更容易验证。

## 限制与演进

- 同一项目同一时刻只接受基于最新版本的写入；冲突用户需要刷新后重做修改；
- 当前不做自动三方合并；
- 大型项目会增加请求体和服务器校验成本；
- 当真实数据规模或协作频率超过内测范围时，改为命令式增量 API，但继续保留项目版本、服务端约束和事务边界。
