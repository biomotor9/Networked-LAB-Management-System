# ADR 0004：以项目作为实验计划的顶层容器

- 状态：已接受
- 日期：2026-08-14

## 背景

原工作区以团队唯一项目承载全部实验计划，无法区分多项独立研究，也无法为不同项目设置负责人、成员、只读访问和独立生命周期。项目本身不参与计划网络计算，因此把它绘制成实验节点会混淆“管理边界”和“执行依赖”。

## 决策

1. 项目是团队内实验计划的顶层容器，不绘制为网络节点；每个计划必须且只能归属一个项目。
2. 计划层级和执行依赖只能存在于同一项目内。允许将完整计划子树移动到其他项目，但存在跨子树依赖或目标 ID 冲突时必须先处理冲突。
3. 项目名称在团队内按去除首尾空白和不区分大小写的规范值唯一。
4. 项目具有“筹备中、进行中、暂停、已完成”人工状态；归档是独立生命周期标记。归档项目只读，默认不显示，只有搜索名称或“已归档”时出现。
5. 项目角色为负责人、成员和访客。负责人唯一；成员可编辑科研内容；访客只读。团队管理员可以查看全部项目和处理成员、归档、恢复与删除，但日常不直接编辑科研内容。
6. 团队管理员需要编辑科研内容时，应加入项目，或创建一段有原因、有有效期且写入审计记录的应急编辑会话。
7. 空项目可由项目负责人或团队管理员永久删除；非空项目只有团队管理员在输入项目名称确认后才能级联删除。项目审计记录保留，项目附件文件随项目删除。
8. 项目元数据、成员变更、状态、归档、恢复、移动、导入、删除和应急编辑均写入审计记录。
9. 旧版本每个团队的唯一项目迁移为“历史实验项目”，旧计划和内容保持原归属，并由有效团队管理员担任负责人。

## 结果

- 工作区必须先选中项目，未选中时不提供创建计划入口。
- 所有工作区接口必须显式携带项目 ID，并在服务端验证团队归属、项目角色、归档状态和应急会话。
- 浏览器缓存按项目隔离；项目切换不能复用其他项目的异步保存结果。
- 导出格式升级为项目级版本，团队导出可包含多个项目；附件二进制不嵌入 JSON。
- 数据库增加项目成员、项目生命周期字段、计划创建者、项目级附件和应急编辑会话，并取消团队唯一项目约束。

## 未采用方案

- 将项目作为计划图中的顶层节点：会把权限和生命周期边界混入实验依赖模型。
- 团队管理员天然拥有科研内容编辑权：不利于职责分离和审计解释。
- 通过项目名前缀持久化归档状态：展示时增加“已归档_”即可，避免名称被生命周期操作反复改写。
