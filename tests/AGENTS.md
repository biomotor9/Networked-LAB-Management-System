# 测试开发规则

本文件适用于 `tests/` 下的自动化测试，并继承仓库根目录和被测功能的局部规则。

## 当前测试地图

| 测试文件 | 主要覆盖范围 |
| --- | --- |
| `domain-logic.test.ts` | 计划树、依赖环和 Markdown 编解码 |
| `content.test.ts` | 文档、Entry、工作区内容和附件名称/大小校验 |
| `persistence.test.ts` | 本地工作区备份、恢复和旧状态规范化 |
| `password.test.ts` | 密码策略、散列验证和临时密码 |
| `server-snapshot.test.ts` | 团队计划快照、层级和依赖约束 |

当前自动化测试尚未直接覆盖 API Route Handler、PostgreSQL 迁移、React 页面交互和完整浏览器流程。涉及这些区域时必须补最小可执行测试，或在交付说明中明确人工验证及剩余风险。

## 选择测试层级

- 纯函数、解析器和校验器：使用快速、确定性的单元测试；
- API 变更：覆盖认证、权限、非法输入、成功路径、并发冲突和稳定错误格式；
- 数据库或迁移：使用隔离测试数据库，覆盖空库创建、上一基线升级、约束和幂等性；
- UI 与交互：优先覆盖关键状态转换，并为登录、保存、冲突和附件流程增加浏览器测试；
- 缺陷修复：先添加能够复现缺陷的回归测试，再实现修复。

## 测试质量

- 不得通过删除用例、降低关键断言、跳过测试或扩大模糊容差来让失败变绿。
- 测试应验证外部可观察行为和关键不变量，避免绑定无关实现细节。
- 每个测试独立创建数据，不依赖执行顺序、生产数据、真实凭据或外部网络。
- 权限和团队隔离测试必须同时包含允许与拒绝场景。
- 新测试文件必须加入实际执行的 npm 测试脚本或测试发现范围；不能只创建文件而不让 `npm test` 运行它。
- 测试运行产生的缓存、数据库和附件必须保持在被忽略的临时位置并可安全清理。

## 完成门槛

先运行与改动直接相关的最小测试集，修复后再运行 `npm test` 和 `npm run lint`。涉及 UI、API、数据库或部署时，继续执行根目录“按变更类型验证”规定的额外检查，并在交付说明中报告结果。
