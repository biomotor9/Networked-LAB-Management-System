# API 开发规则

本文件适用于 `app/api/` 下的所有 Route Handler，并继承 `app/AGENTS.md` 和仓库根目录规则。

## 开发前读取范围

优先读取当前 `route.ts`、它直接调用的 `app/lib/` 模块、相关数据库表和对应测试。只有在接口改变共享响应结构或数据模型时，才检查其他接口。

## 接口约束

- 除健康检查和登录等明确公开入口外，接口必须验证会话；团队或项目资源还必须验证访问权限。
- 不信任客户端传入的用户、团队、项目、文件名、内容类型、版本号或记录 ID。
- 输入必须在数据库写入或文件操作前完成类型、长度、关联关系和权限校验。
- 使用稳定、明确的 HTTP 状态码和 JSON 错误格式；不要向客户端返回堆栈、数据库错误、密码散列、令牌或服务器路径。
- 修改团队数据时保留现有乐观并发、审计和事务语义，不通过额外接口绕开冲突检测。
- 附件下载与上传必须复用 `app/lib/attachments/` 和既有校验规则，防止路径穿越、超限和不安全文件名。
- 认证相关响应必须保持 Cookie 安全属性、首次改密和停用账户检查。

## 变更检查

- 接口字段变化时同步检查调用方、服务端校验、数据库映射和备份导入导出。
- 新增写接口时确认是否需要审计事件、并发版本或事务。
- 新增路由后运行相关单元测试、`npm run lint` 和 `npm test`。
