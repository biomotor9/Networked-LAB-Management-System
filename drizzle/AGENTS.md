# 数据库迁移规则

本文件适用于 `drizzle/` 中的 SQL 迁移和 Meta 文件，并继承仓库根目录规则。

## 不可破坏的约束

- 已经发布的 `0000` 至 `0003` 迁移视为不可变历史，不得改写、重命名、重新排序或删除。
- 数据库结构变化必须从当前 `db/schema.ts` 生成新的迁移文件。
- 新迁移必须与 `meta/_journal.json` 和对应快照一起提交，不能只手写 SQL 而遗漏 Drizzle 元数据。
- 迁移应能在已有生产数据上向前执行；新增非空字段、唯一约束或外键前必须考虑历史数据。
- 不把删除列、清空表或不可逆数据重写作为默认方案。确需破坏性迁移时，必须明确说明影响、备份和回滚方式。
- 不依赖修改旧迁移来修复生产问题，应新增修复迁移。

## 验证

- 审阅生成的 SQL，确认目标表、默认值、索引和约束符合预期。
- 至少验证从空数据库执行全部迁移；涉及已有数据时还要验证从上一生产版本升级。
- 发布前必须生成数据库备份；不兼容迁移必须准备数据库恢复方案。
